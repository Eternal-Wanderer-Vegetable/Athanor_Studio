# Athanor Studio：CI + A2 AI 管线示例 + B1 Paged.js/CDP 出版 实施计划

**已确认的决策**：CI 用 GitHub Actions ubuntu+windows 双矩阵；B1 走最小自实现 CDP（tungstenite）；Paged.js polyfill vendor 进 crate。

---

## 任务 1：创立 CI 流程

仓库托管在 GitHub（`Eternal-Wanderer-Vegetable/Athanor_Studio`），当前**无任何 CI**。

**新建 `.github/workflows/ci.yml`**：
- 触发：push 到 main、pull_request、workflow_dispatch。
- 矩阵：`ubuntu-latest` + `windows-latest`（Windows 是项目主平台，双平台才有意义）。
- 步骤：checkout → `dtolnay/rust-toolchain@stable`（含 rustfmt/clippy 组件）→ `Swatinem/rust-cache` →
  1. `cargo fmt --all -- --check`
  2. `cargo clippy --workspace --all-targets -- -D warnings`
  3. `cargo test --workspace`
- Windows 侧加 `choco install pandoc -y`（DOCX e2e 可跑；ubuntu-latest 预装 pandoc）。
- 浏览器覆盖：windows 自带 Edge；ubuntu 有 `/usr/bin/google-chrome`——现有 `find_browser` 的 PATH 搜索列表（azodoc-pdf/src/lib.rs:107）只找 `msedge/chrome/chromium`，**补充 `google-chrome`、`google-chrome-stable` 两个名字**（低风险小改动）。若 ubuntu 上 Chrome 因沙箱起不来，启用 `--no-sandbox` 的应急开关留到实际失败再处理。

**前置修复**：代码从未跑过 fmt/clippy 严格检查，先在本地跑 `cargo fmt` 与 `cargo clippy --workspace --all-targets`，把琐碎警告清零（确属误报的用局部 `#[allow]` + 注释），保证 CI 首推即绿。

## 任务 2：A2 语义层 AI 管线示例（S 规模）

**验收对照 Future Work A2**：示例跑通全流程；AI 落链可 `history` 审计；AI 标注带 confidence。

**新增文件**（约 250 行核心 + 薄壳，符合文档 "~200 行示例" 预估）：
1. `engine/crates/athanor-cli/src/ai_demo.rs`（lib 模块，便于测试复用）：
   - `trait AiProvider { name(); complete_json(system, user) -> Value }`，两个实现：
     - `FakeProvider`：内嵌确定性应答 JSON，**离线可跑、CI 可测**（默认，未配置环境变量时启用）；
     - `HttpProvider`：ureq（rustls）POST OpenAI 兼容 `{AZODOC_AI_BASE_URL}/chat/completions`，`response_format: json_object`；密钥/模型走 `AZODOC_AI_API_KEY` / `AZODOC_AI_MODEL` 环境变量。
   - `pub fn run(path, provider) -> Result<AiDemoResult>`：读容器 → 抽取块（ID+纯文本）→ 组 prompt（要求返回 `{"annotations":[{block,type,value,confidence,exact}], "rewrites":[{block,new_text,reason}]}`）→ **校验 LLM 返回的块 ID 真实存在**（丢弃幻觉 ID）→
     - 标注走现有 `cmd_annotate`（author `ai:<model>`、confidence、source `ai_pipeline`）；
     - 改写：直接改 `document/content.json` 目标块文本 → `cmd_commit`（author `ai:<model>`，message 取 reason）。
2. `engine/crates/athanor-cli/examples/ai_pipeline.rs`：薄壳入口，参数 `<doc.azodoc> [--provider fake|http]`，跑完后打印 `history`/`annotations`/`checkout` 人工复核指引（对应文档"人工 review 后 checkout/upgrade"）。
3. `engine/crates/athanor-cli/tests/a2_tests.rs`：`cmd_new`+`cmd_import(corpus/markdown/basic.md)` 造文档 → FakeProvider 跑 `ai_demo::run` → 断言：标注层有 `author.type=="ai"` 且带 confidence；修订链头部 `author_type=="ai"`（history 可审计）；`verify_cmd::run()==0`。
4. 依赖：workspace 增 `ureq`（默认 rustls，无 openssl 负担），仅 athanor-cli 使用。

## 任务 3：B1 Paged.js/CDP 出版（M 规模）

**验收对照 Future Work B1**：多页文档页脚含页码；分页点由 Paged.js 决定；layout_hash 确定性；产出非空白。

1. **资产 vendor**：复制 `tools/pagedjs/paged.polyfill.js` → `engine/crates/azodoc-pdf/assets/paged.polyfill.js`（.gitignore 只忽略 tools/，可正常入库），crate 内附 MIT 来源/版本注记。
2. **`azodoc-pdf/src/cdp.rs`（新，约 300 行，最小 CDP 客户端）**：
   - 启动浏览器（`--headless --remote-debugging-port=0 --user-data-dir=<tmp>`），后台线程读 stderr 解析 `DevTools listening on ws://…`；
   - tungstenite WebSocket（127.0.0.1，无需 TLS，`default-features=false, features=["handshake"]`）+ JSON 帧路由（id/response 匹配、sessionId 会话、事件等待）；
   - 命令序列：`Target.createTarget` → `Target.attachToTarget(flatten)` → `Page.enable` → `Page.navigate(file://…)` → 等 load → 轮询 `Runtime.evaluate("window.__azodocPagedDone===true")`（由 HTML 内注的 `window.PagedConfig={auto:true, after:()=>{window.__azodocPagedDone=true}}` 置位，**从根上消除文档记录的 virtual-time-budget 竞态**）→ `Runtime.evaluate` 取 `.pagedjs_page` 数与页脚文本样本 → `Page.printToPDF(preferCSSPageSize, printBackground)` → base64 解码写文件（复用 workspace 已有 base64 依赖）→ `Browser.close` + kill 子进程。
3. **`azodoc-pdf` 增加 `print_html_to_pdf_paged()` 与 `augment_print_html()`**：注入 PagedConfig script + `<script src="./paged.polyfill.js">`（polyfill 同步写到临时目录），加 Paged 版印刷 CSS 增量：`@bottom-center { content: counter(page) }` 页脚页码、隐藏元素 `string-set` 运行头（文档标题）。
4. **`commands_m5.rs` 编排改造**：`PublishArgs` 增 `no_paged`（CLI `--no-paged` 退出开关）；默认走 CDP+Paged.js，**失败时告警并回退现有直印路径**（不伤核心原则）；`publication.json` 的 `renderer.engine` 记 `chromium-cdp/pagedjs (…)` vs `chromium-print (…)`；**layout_hash 输入加入模式串**（pagedjs/plain），CSS 版本升 `print-css-v2`；`page.count` 优先取 Paged.js DOM 实数。
5. **测试**：
   - 无浏览器单测（CI 必跑）：`augment_print_html` 注入断言、stderr ws 地址解析器、CDP 消息编解码、base64 解码；
   - e2e（沿用 m5_tests 浏览器缺席跳过模式）：多页语料（程序化重复段落）→ publish → 断言 publication.json `page.count>=2`、页脚样本含页码、两次出版 layout_hash 一致、`verify==0`、`--no-paged` 路径仍通。

## 执行顺序与工程规约

**顺序**：CI（含 fmt/clippy 前置清理）→ A2 → B1，各自独立提交，方便回溯。
**GitNexus 规约**（AGENTS.md 强制）：每次编辑符号前跑 `impact` 分析（重点：`cmd_publish`、`PublishArgs`、`find_browser` 的上游调用方）；每次提交前跑 `detect_changes --scope all`，HIGH/CRITICAL 风险先报告。
**收尾文档**：README 测试数与新特性更新；Future Work 文档 A2/B1 标注"已实现（2026-09）"。

**风险与预案**：fmt/clippy 首跑可能大量琐碎告警（逐条清理）；ubuntu 无头 Chrome 沙箱问题（留应急开关）；Paged.js margin-box 兼容性以真机 e2e 验证为准。
